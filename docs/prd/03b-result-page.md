# 03b · 结果页 UI（对照卡 · 证据档 · 申诉信 · 路线图）

> 母文档 §3.5。**产品的全部差异化都长在这一页上**——第二层「扣款 ↔ 证据 ↔ 合同 ↔ 法条」的对照关系必须被人一眼看懂。视觉与响应式约束见 `docs/design-tokens.md`（唯一事实源，先读它）。

**开工前提**：04a 的示例常量已就绪 → **先用它当假数据把整页画完**，最后才接 03a 的真接口。

## 文件所有权（并行纪律）

| 你拥有 | 你不许碰 |
|---|---|
| `app/result/page.tsx` | `lib/types.ts`（前置已冻结） |
| `components/result/**` | `app/api/**`、`lib/prompts/**`、`lib/analysis-*.ts`（属 03a） |
| `lib/pdf-letter.ts`（jspdf 客户端生成） | `data/sample-case/**`、`components/evidence/**`（属 04a，你只 import） |

## 1. 首屏（手机 ~560px 内看全四件事）

主数字坐在**深色账本条**上——`--color-amount-hero` 在浅色纸面对比度只有 1.99:1，不可读；在墨蓝底上是 7.58:1。`components/wizard/ledger-bar.tsx` 已是这个模式，照抄它的做法。

```
房东索扣 $1,306
█████████▓▓▓▓░░                    ← 三色堆叠条
❌$780 不合法  ⚠$340 待举证  ✅$186 合法

   可争议  $1,120
   应退回至少 $3,374

• 地毯：入住报告已记录原有污渍
• 花园：合约未见此义务，该房东举证
• 水费：合法，别争

[看逐项依据]   [生成申诉信]
```

- 堆叠条按 `ledger` 的三个金额分段，颜色用 `verdict-*-on-dark`
- 三行「为什么」各取一笔扣款的一句话（从 `reasoningZh` 截取或由数据提供）
- `mode === 'burden-shift'` 时首屏顶部加一条标注：「举证责任翻转模式（未上传证据）」
- 360px 下账本条金额与按钮换两行，不得溢出

## 2. 逐项对照卡（固定四行，最重要的组件）

```
┌ ① 退租专业清洁 + 地毯蒸洗   $780   ❌ 不合法 ┐
│ 证据  入住报告 P3 · 客厅地毯                │
│       "Carpet: existing stains noted"   ← 可点击定位
│ 合同  笼统的专业洗地毯条款可能无效           │
│ 法条  RT Act 2010 (NSW) s 30 · s 51(3)(c) · s 19
│ 结论  入住时已有污渍，房东不得就此扣款        │
└ 可争议 $780                                ┘
```

- **四行标签用 `text-micro`**（全大写小标签），内容用 `text-label`/`text-body`
- 三档结论**必须同时有图标 + 颜色 + 中文标签**，不得只靠颜色（色觉可及性，成本为零）
- 法条行显示 act + section；点开展开原文 `quote` 与 `sourceUrl` 外链
- **证据行点击 → 滚动并高亮到证据原件对应位置**（调用 04a 的 `ConditionReportDoc` 暴露的定位 API）
- 三轴 `checks` 的展示：`unknown` / `n-a` 不要显示成「否」，用「未知」「不适用」或直接省略该行

## 3. 证据档

「AI 从 N 份证据读到 M 条事实」——**已被采用的打钩（`evidence-used`），未用到的也列出（`evidence-unused`）**。这证明 AI 通读过全部材料，而不是只挑了用得上的那几条。默认折叠，标题即可看到 N/M。

## 4. 申诉信

- `textarea` 可编辑（编辑不回写分析结果）
- 「下载 PDF」：`jspdf` 纯文本英文信排版，无需嵌中文字体
- 「复制全文」：微信内置浏览器下载受限时的兜底，必须存在且好用
- 中文对照解释（`letterZhNotes`）在信下方展示，**不进 PDF**

## 5. 行动路线图

按州从 `data/legal/` 的 `stateProcesses` **确定性渲染**（Fair Trading/CAV → NCAT/VCAT 路径、费用、时限），LLM 只填个性化字段。含邮件留证话术模板与抢先向 RTBA/RBO 发起 claim 的指引。

**存管卡是第 1 步**：`verify-record` 黄色「先去查 RBO/RTBA」；`possible-non-lodgement` 及以上为红色并**必须展示计算依据**（日期 + 适用期限 + 来源）。任何等级都不得把 penalty units 写成租客自动获赔。

## 6. 分析进度（真实两段）

| 阶段 | 进行中文案 | 完成时 |
|---|---|---|
| `/api/facts` | 「正在阅读你的入住报告…」 | 「读到 N 条事实」 |
| `/api/analyze` | 「正在对照 NSW 租赁法…」 | 「比对了 M 条法条」 |

- 是**进度动画，不是聊天气泡**，也不是假进度——两段与真实调用一一对应
- 某一段失败 → 指出失败在哪一段，可**单独重试那一段**，不要求从头再来
- 全程失败 → 体面降级提示 + 重试按钮，绝不白屏

## 7. 桌面布局（≥1024px）

```
┌────────────────┬──────────┐
│ 账本条 $1,306   │ 申诉信    │
│ 可争议 $1,120   │（sticky） │
├────────────────┤──────────┤
│ 对照卡 ①❌      │ 行动路线  │
│ 对照卡 ②⚠      ├──────────┤
│ 对照卡 ③✅      │ 证据档    │
└────────────────┴──────────┘
```

容器 `max-w-[1152px]`，左 `1fr` / 右 `380px`。**只能用 `lg:` 改结构**，`md:` 只许加宽加间距。手机堆回单列，顺序不变。

## 8. 验收标准

- [ ] 手机首屏能同时看到：被扣多少、可争议多少、三条为什么、两个 CTA
- [ ] 每张对照卡同时可见：证据引语 + 定位、合同判定、法条编号、中文结论、该项可争议金额
- [ ] **点证据引语 → 入住报告滚动并高亮到对应行**
- [ ] 三档结论在任何位置都有图标 + 颜色 + 中文标签
- [ ] 证据档显示 N/M，未采用的事实也列出
- [ ] 申诉信可编辑、可下载 PDF（iPhone Safari + 桌面 Chrome）、可复制全文
- [ ] 路线图费用/时限来自 `stateProcesses`，非 LLM 生成
- [ ] 存管红色提示必须展示计算依据
- [ ] 两段进度与真实调用对齐，完成时报出真实条数；单段失败可单段重试
- [ ] `mode: 'burden-shift'` 时首屏有模式标注，页面不是一片 ⚠️
- [ ] 桌面 ≥1024px 双栏 + 右栏 sticky；360px 无横向滚动
- [ ] 直接访问或刷新空的 `/result` 有可恢复提示，不白屏
- [ ] 所有组件接受纯 props（供 04b 复用）
- [ ] `pnpm check:tokens` 零违规

## 9. 不做

- 结果持久化/分享链接；流式输出；服务端逻辑（属 03a）
- 战报卡（属 04b）
