# 04 · 首页双入口 + 预制示例案例 + 战报卡（任务 5 · 3h）

> 母文档 §3.1、§3.6、§4。人气赛的传播弹药库：示例案例是多数投票者唯一会走的路径。

## 首页

- 入口一「😤 我的押金被扣了」→ `/wizard` 真实流程
- 入口二「👀 先看个案例」→ `/sample` 预制示例
- **愿景橱窗**区块（06 未解锁时的默认形态）：即将支持——QLD/WA、入住留证、中介往来助手
- 一句话价值主张 + 视觉主视觉（写 UI 前调 `frontend-design`：这是投票者的第一眼）

## 预制示例案例（`/sample`）

- **静态数据、零 API 调用**：`data/sample-case/` 内硬编码一份 `CaseInput` + `AnalysisResult`，**完全复用 03 的结果页组件**（既省时间又保证演示与真实一致）
- 案情（按真实小红书案例改编）：押金 $3,560、被索扣 ~$800
  - 地毯污渍 ❌ —— 入住报告已标注原有损耗
  - 草坪维护 ❌ —— 合同无此义务
  - 墙面钉眼 ❌ —— 房东原有痕迹 + 合理磨损
  - 一笔 ✅ 合法别争 —— 展示诚实与可信度
- **文案逐字手工打磨**（不由 AI 现场生成后直接采用）
- 页脚注明：「这是预载示例，你的案子会实时分析」

## 战报卡（结果页与示例页均有）

- 可保存的分享图卡：文案如「AI 帮我追回 $1,120」+ 产品二维码 + 品牌视觉
- 实现：DOM → PNG（html-to-image）渲染为 `<img>`，微信内长按即可保存——**分享即拉票**
- 二维码指向部署 URL

## 验收标准

- [ ] 示例页面加载 < 1s、断网可看（纯静态）
- [ ] 示例页与真实结果页视觉完全一致（同组件）
- [ ] 战报卡在微信内长按可保存，二维码可扫、扫开是产品
- [ ] 首页在手机首屏内讲清「是什么 + 两个入口」

## 不做
